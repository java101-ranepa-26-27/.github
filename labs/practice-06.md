## Как получить эту лабу

Эта лаба — начало итогового проекта. Проект создаётся из шаблона `java101-template`.
Шаблон редактировать нельзя — сделай **свою копию**:

1. Открой страницу шаблона: **https://github.com/java101-ranepa-26-27/java101-template**
2. Нажми зелёную кнопку **Use this template** → **Create a new repository**.
3. **Owner** — выбери организацию **java101-ranepa-26-27**.
4. **Repository name** — `java101-<lastName>-final`, где `lastName` — фамилия латиницей.
   Имя должно быть уникальным в организации.
5. **Visibility** — оставь **Private**.
6. Нажми **Create repository**.

Клонируй его в IDE: на странице своего репозитория — зелёная кнопка **Code** → **HTTPS** → скопируй
ссылку, затем в IDE **File → New → Project from Version Control…** → вставь ссылку → **Clone**.

## Как завести ветку

В OpenCode нажми на текущую ветку в правом нижнем углу окна — там написано `main`.
Выбери **New Branch…**, введи `task-6` и нажми **Create**.

## Что делаем

Это каркас итогового проекта. Логики пока нет: нужны классы, меню и `// TODO` вместо методов.

Программа запускается, показывает меню и выполняет команды. Внутри команд пока ничего не
происходит: меню вызывает сервис, а в сервисе стоит `// TODO`.

Вариант — тот же, что в итоговом проекте.

### Пакеты

Нужны пять пакетов. Вместо `<домен>` — тема варианта маленькими английскими буквами:
`library`, `hospital`, `shop`.

| Пакет | Что в нём |
|---|---|
| `ru.ranepa.<домен>` | `Main` |
| `ru.ranepa.<домен>.domain` | сущности варианта |
| `ru.ranepa.<домен>.application` | сервисы |
| `ru.ranepa.<домен>.application.port` | интерфейсы репозиториев |
| `ru.ranepa.<домен>.infrastructure` | `InMemory...Repository` и `ConsoleMenu` |

Репозиторий — это класс, который хранит список объектов. Не Git-репозиторий.

### Что лежит в пакетах

**`domain` — сущности.** Классы из ТЗ варианта. У каждого: поля (`private`), конструктор, геттеры.

**`application.port` — интерфейсы репозиториев.** Для каждой сущности — свой интерфейс.
В интерфейсе три метода: добавить, вернуть всех, найти по имени.

**`application` — сервисы.** У каждой сущности — свой сервис. В сервисе:

- поле с типом интерфейса репозитория;
- конструктор, который принимает этот репозиторий;
- методы действий из ТЗ. Вместо логики — `// TODO`, вместо ответа — `null`, `0` или `false`.

**`infrastructure` — репозитории и меню.** Для каждого интерфейса — класс
`InMemory...Repository`, который его реализует. Внутри — методы с `// TODO`.

`ConsoleMenu`:

- поле `Scanner`;
- поля с сервисами;
- конструктор принимает `Scanner` и сервисы;
- метод `run()`: цикл, печать меню, чтение команды, `switch`.

В каждом пункте меню — вызов метода сервиса.

**`Main` в корневом пакете.** Создаёт репозитории, передаёт их в сервисы, передаёт сервисы
в меню и запускает меню.

### Кто кого вызывает

```text
Main → создаёт репозитории, сервисы и меню
ConsoleMenu → вызывает сервисы
Сервис → обращается к репозиторию через интерфейс
InMemory...Repository → реализует интерфейс репозитория
```

### Меню

- **1** — добавить главную сущность;
- **2** — добавить вторую сущность;
- **3** — показать всех;
- **4** — найти главную сущность по имени;
- **5** — операция из твоего варианта;
- **6** — статистика;
- **0** — выход.

Названия команд и что именно они делают — из ТЗ варианта.

### Подсказка: как разложить ТЗ по классам

Смотри на слова в ТЗ варианта.

- **Существительное** — это сущность. Она идёт в `domain`.
- **Действие** — это метод сервиса. Он идёт в `application`.
- **Список объектов** — это репозиторий. Интерфейс — в `application.port`,
  класс `InMemory...` — в `infrastructure`.

Пункт меню — это вызов метода сервиса.

Пример. В ТЗ есть «книга» и «читатель».

- `Book` и `Reader` — сущности в `domain`.
- «Добавить книгу», «показать все книги» — методы `BookService`.
- Список книг — `BookRepository` и `InMemoryBookRepository`.
- Пункт меню «1 — добавить книгу» вызывает метод `BookService`.

Проверки из ТЗ («нельзя пустое имя», «оценка 2–5») — в сервисе.

`Main` создаёт репозитории, сервисы и меню.

## Сдача работы

После выполнения работы выполняется коммит + пуш + Pull Request в `main`.

### Как открыть Pull Request

1. Открой страницу своего репозитория на GitHub и обнови её. Сверху появится жёлтая плашка
   **Compare & pull request** — нажми её.
2. Проверь направление слияния: **base: `main`**, **compare: `task-6`**.
3. В поле **Title** напиши, например, `Практика 6: каркас итогового проекта`.
4. В описании PR добавь **скриншот выполнения класса `Main`**.
5. Нажми **Create pull request**.
